# Xedine for Android (ADR 0065)

A Trusted Web Activity: Chrome showing https://xedine.org full screen, generated by Google's Bubblewrap.
Every website deploy reaches the app at once; this folder only changes for the app's own settings.

| Path | What it is |
| --- | --- |
| `twa-manifest.json` | **The source of truth**: package, name, colours, icons, shortcuts, version, fingerprints |
| `tools/generate-project.mjs` | Regenerates the Gradle project from it and applies Xedine's changes |
| `make-icons.py` | Maskable, monochrome and full-bleed icons from the chef tile (`public/brand/`) |
| `tools/store-graphics.mjs` | Shortcut icons and Play feature graphics |
| `tools/store-screenshots.mjs` | Play screenshots of the live site (demo restaurant) |
| `build.ps1` | Builds the signed `.aab` and `.apk` into `release/` (git-ignored) |
| `app/`, `gradle/`, `*.gradle` | Generated. Do not edit by hand: the next generation overwrites it |

## Build

```powershell
powershell -ExecutionPolicy Bypass -File E:\xedine.org\android\build.ps1
```

On the founder's PC everything lives on E:, because C: is full:

- `E:\android-tools\jdk-17`: Temurin JDK 17.
- `E:\android-tools\sdk`: platform 36, build-tools 35/36, command-line tools 19.0.
- `E:\android-tools\gradle-home`: Gradle's cache.
- `E:\Xedine-Android-Keys`: the upload key, its password and `keystore.properties`. **Back it up; never commit it.**

The PC's hosts file blocks `dl.google.com`, which stops Chrome updates. So:

- The SDK came from the `dl-ssl.google.com` mirror, installed with `SDK_TEST_BASE_URL`.
- `E:\android-tools\gradle-home\init.d\google-mirror.gradle` points Gradle's `google()` there.
- The newest command-line tools (20+) fetch an "Android CLI" from `dl.google.com`, so 19.0 is kept.

On any other machine with JDK 17 and the Android SDK, set `ANDROID_HOME` and `XEDINE_KEYSTORE_PROPERTIES`
and run `./gradlew bundleRelease`. Without a key, the release build is left unsigned and Gradle warns.

## Change the app

1. Edit `twa-manifest.json`. For a Play upload, raise `appVersionCode` and `appVersion`.
2. `node android/tools/generate-project.mjs`, or add `--local` while new icons are not deployed yet.
3. `build.ps1`, then upload `release/xedine-<version>-<code>.aab`.

`src/lib/android-app.test.ts` checks that `twa-manifest.json` agrees with `public/manifest.webmanifest` and
`public/.well-known/assetlinks.json`. A new signing key's SHA-256 goes in **both**
`fingerprints` and `assetlinks.json`.

Launch steps and store answers: [docs/play-store/README.md](../docs/play-store/README.md).
